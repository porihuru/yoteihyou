# 予定表

Edge 95 と Internet Explorer 11（IEモードを含む）で動作する、SharePointリスト連携の月間予定表です。

導入・保守時は **[SharePointリスト点検一覧](#sharepoint-list-check)** で、リスト・列・初期データ・権限を確認できます。

## グループ別の標準予定表への切替（今回の改修）

`sharePoint.groupCalendars: true` を既定にしました。大グループ・小グループの階層と登録順はそのまま、各グループに指定したSharePoint標準予定表を集約します。設定画面に「予定表サイトURL」「予定表リスト名」「接続確認」を追加しています。予定表の作成はSharePoint側で行い、アプリに接続先を登録します。

### 導入手順

1. グループごとに、SharePointの標準「予定表」を作成します。予定表側の列追加は不要です。標準の `Title`、`EventDate`、`EndDate`、`fAllDayEvent`、`Category`、`Location`、`Description` を使用します。下記の旧方式の `AllDay`、`Purpose`、色の独自列は追加しないでください。
2. **予定表組織設定リスト**に、内部名 `CalendarSiteUrl` と `CalendarListTitle` の「1行テキスト」列を追加します。どちらも入力必須を「いいえ」にします。予定を保存する各予定表への追加ではありません。
3. 共通の**予定表配置設定リスト**を用意します。既存の `Title` は一意、`LayoutJson` は「複数行テキスト／書式なしテキスト／変更履歴の追加なし」とします。拡張リッチテキストではJSONを読み込めません。従来の上下配置に加え、反映先（日々・週間・月間）と色などを `events:予定表GUID` という別項目に保存します。既存の配置項目は維持します。
4. 配布ファイルをまとめて更新します。新しい `js/group-calendar-source.js` も必要です。`js/config.js` の共通サイトURLを確認し、ブラウザーのキャッシュを更新します。
5. 「予定表更新」→「設定」で、各グループの予定表リスト名と必要に応じてサイトURLを入力し、接続確認して保存します。サイトURLが空欄なら共通サイトを使用します。接続確認は標準予定表と列の読取を確認します。書込権限は実際の保存時に確認されます。
6. 対象グループで試験予定を新規作成し、再読込、修正、削除を確認します。各予定表と共通補助リストの読込・編集権限が必要です。別サイトを指定する場合もブラウザーから接続可能な同一オリジンの構成を基本とします。

### グループと保存先

| グループ設定 | 接続・表示 |
|---|---|
| 小グループのない大グループ | 大グループ自身の予定表を指定 |
| 小グループのある大グループ | 小グループごとに予定表を指定 |
| 大グループ共通の予定も必要 | 小グループなしの大グループ行も登録し、別の予定表を指定 |

大グループ共通の行はその小グループより上に表示します。同じ予定表を複数グループに重複登録することはできません。新規予定は選択したグループの予定表へ保存し、修正・削除は元の予定表を対象にします。予定表GUIDと項目IDの組合せで識別するため、別リストの同じ項目IDは混ざりません。

SharePoint側で直接追加した予定は、補助設定がなければ「日々・週間・月間すべて」、標準色・標準配置で表示します。未設定・接続失敗・補助設定読込失敗はグループ名付きで画面に表示し、接続できたグループの表示を続けます。失敗したグループへの書込は止めます。

### 移行と制限

- 標準予定表の終日予定は、読込時には応答の日付をそのまま扱い、保存時にはPCの現地日付の00:00～23:59をUTCへ変換して送信します。PCとSharePointサイトのタイムゾーンは一致させてください（運用環境は日本時間）。保存後に再取得し、入力日付と違う場合は両方の日付を警告表示します。自動再保存はしません。終日の間は時刻欄を隠します。旧版で既に誤った日付を保存した予定は自動短縮しません。本来の日付を確認し、必要な予定だけ修正してください。

- **既存予定は自動移動しません。** 接続先の変更でもデータは移りません。旧リストは残したまま、必要な予定を確認して移行してください。
- 標準予定表への保存と補助設定への保存は一括処理ではありません。本体の保存後に補助設定の保存が失敗した場合は警告を出します。新規予定をもう一度作らず、再読込して対象予定の反映先・色を確認してください。補助設定はETagで競合を検出します。
- 修正画面から別の予定表へ直接移動する操作は止めています。移動先へコピーし、保存を確認してから元の予定を削除してください。
- 繰り返し予定の展開は未対応です。取得した繰り返し予定は誤表示を防ぐため除外し、警告を出します。繰り返し予定はSharePoint側で確認してください。
- CSV試験モードは維持しています。旧単一リスト方式に戻す場合は `groupCalendars: false` とします。旧組織設定リストに新しい2列を追加していない場合は、`organizationSettings.fields` の `calendarSiteUrl` と `calendarListTitle` の指定も外してください。

確認コマンドは `node tests/run-tests.js`、`node tests/group-calendars.test.js`、`node tests/all-day.test.js` です。テストは通信を模擬して保存先・ID重複・部分失敗・標準列・競合情報などを検証します。終日予定は日本時間・UTC・米国時間で読込と保存を繰り返して日付を確認します。実際のSharePoint、Edge 95、IE11での動作確認は導入先で別途必要です。

## 表示と印刷

### 休日設定

「予定表更新」→「設定」→「休日設定」で、1行に `2026-12-29 | 年末休業` のように日付と名称を入力します。行の追加・書換え・削除で編集し、「休日を共有保存」で確定してください。日付の重複・不正日付は保存できません。独自休日や削除に伴う振替休日は自動生成しません。日曜日自体は休日一覧から削除しても赤色のままです。

初期値は2026～2028年の49件です。2026年18件・2027年17件は[内閣府の公表一覧](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)、2028年14件は現行法の固定日・曜日規則から算出しました（2026-10-02確認）。2028年の春分・秋分の日は正式決定前なので登録していません。2027年2月の公表後に設定から追加してください。[国立天文台の確定時期の説明](https://www.nao.ac.jp/faq/a0301.html)。土日、年末年始休業等を別の休日項目として一括追加するものではありません。

保存先は既存の「予定表配置設定」リストの `Title=holidays-v1` の1項目で、`LayoutJson` に日付・名称の配列を保存します。予定表の列追加や新規リスト作成は不要です。`LayoutJson` は書式なし複数行テキスト、`Title` は一意にしてください。起動時は読込のみで、初回の共有保存時に項目を作成します。他の配置項目や予定は変更しません。ETagによる競合検出があり、空一覧を保存した場合も初期値には戻しません。リスト読込失敗時は初期値または直前の表示を維持して設定画面に警告し、再読込成功まで保存できません。CSV試験中も休日設定は共有リストに保存します。ほかの利用者はページ再読込または「休日を再読込」で反映してください。

週間・月間の休日見出しと列背景は、日曜日と同じ赤系になります。日々は日付見出しを赤色にし休日名を併記します。印刷にも同じ設定が反映されます。テストは `node tests/holidays.test.js` です。

画面上部で次の表示を切り替えます。

- 日々: グループを縦、時刻を横にして1日分を表示。印刷の初期設定はA3横
- 週間: 月曜日から日曜日までを表示。印刷の初期設定はA4縦
- 月間: 月間カレンダーを表示。印刷の初期設定はA3横

下へスクロールしても、データ接続・操作欄と日々の時刻行、週間・月間の日付見出しを画面上部に固定します。月間の横スクロールにも見出しを合わせます。IE11向けにJavaScriptで固定し、印刷時は通常のレイアウトに戻します。

「印刷」または `Ctrl+P` で印刷プレビューを開きます。A4/A3、縦/横、印刷するグループ、横と縦の縮尺を選び、確認してから「印刷する」を押します。内容は用紙に収まる基準寸法で配置され、縮尺はその基準に対する割合です。横の縮尺は列幅、縦の縮尺は行高を変更し、文字は縦横比を保って大きさを変えます。用紙からはみ出す場合は警告を表示します。設定は日々・週間・月間ごとにCookieへ保存され、「設定」のCookie初期化で削除できます。余白は `js/config.js` の `print.marginMm` で変更できます。

予定の入力時に「日々」「週間」「月間」から反映先を複数選択できます。反映先が保存されていない従来データは、3つすべてに表示します。

## 入力と修正

「設定」の「共通の文字設定」で、文字のフォント（標準・メイリオ・ＭＳ ゴシック・ＭＳ 明朝）と基準サイズ（12〜20px）を変更できます。選択すると画面で確認でき、「予定表更新」モードで「文字設定をリストに保存」を押すとSharePointへ保存します。全利用者が起動時に同じ設定を読み込みます。開いている画面には「文字設定を再読込」で反映できます。印刷する予定表にも適用されます。端末にないフォントは代替フォントで表示します。文字設定はCookieには保存せず、Cookie初期化でも変更しません。リストを読み込めない場合はエラーを表示し、起動時は標準、操作中は現在の文字表示を維持します。

起動時の予定表は「読取専用」です。予定や組織設定を変更するときは画面上部の「予定表更新」を押してください。作業後は「更新終了」で読取専用へ戻せます。接続先を切り替えた場合も読取専用に戻ります。更新モードは端末へ保存しません。

- 表示中の予定をクリックすると、内容を直接修正できます。
- 月間画面は日付枠の空白、週間画面は各日の予定欄の空白をクリックして新規入力します。クリックした日付が開始日時・終了日時へ自動設定されます。
- 日々画面は時間枠の空白をクリックして新規入力します。クリックした日付と時刻が開始日時へ入り、終了日時は設定された標準時間後になります。
- 編集中は画面を分割し、左側4分の3に予定表、右側4分の1に入力・修正画面を表示します。
- 入力・修正画面は取消ボタンまたはEscキーで閉じられます。
- 試験用CSVでも新規登録・更新・削除を試せます。変更は画面上だけに反映され、再読込・接続先切替・ページ終了で消えます。CSVファイル自体は更新しません。

週間・月間は日付ごとの表のまま、日々と同じ線種・色、時刻・件名・場所を表示します。予定全体を日付やグループへドラッグして移動できます。横線の端をドラッグする開始日・終了日の変更機能は削除しました。開始・終了を個別に変更する場合は予定編集画面を使用してください。右クリックまたは `Ctrl+C` / `Ctrl+X` / `Ctrl+V` のコピー・切り取り・貼り付けにも対応します。週間・月間には分単位の時間軸がないため、ドラッグで日付を変更しても元の時刻は維持します。

日々画面の時間枠は `js/config.js` の `dailyView` で変更できます。通常は7時から18時までを表示します。6時台または18時以降は、その時間帯に同日内で完了する時間指定予定がある場合だけ表示します。終日予定と複数日にまたがる通し予定は表示範囲を広げる判定に含めません。表示可能範囲は6時から22時、目盛りは1時間単位、標準予定の開始時刻は9時、標準時間は1時間です。

日々画面では、表の時刻目盛りを `0900` 形式で表示します。予定は実際の開始・終了位置を横線で結び、両端へ時刻、線の下へ「件名（場所）」を表示します。多くの予定を表示できるよう、文字サイズを維持して上下の余白を詰めています。予定内の上下余白は各1px、グループ枠側は各2px、予定段の間隔は2pxです。時間が重なる予定は別の表示行へ自動配置します。

日々画面では次の操作にも対応します。時間の変更は15分単位です。

- グループ名の左にある「－」で最小化し、「＋」で展開できます。大グループを最小化すると配下の小グループをまとめて隠し、小グループを最小化するとその予定行を隠してグループ名の1行だけを残します。この状態は日々・週間・月間の表示を切り替えても維持します。
- 件名をドラッグすると、時刻またはグループを変更できます。
- 横線の端による開始時刻・終了時刻の変更機能は削除しました。予定編集画面で変更してください。
- 予定を右クリックすると、コピー、切り取り、貼り付けを選べます。貼り付け先のグループと時刻を右クリックしてから貼り付けます。
- 予定を選択した状態では `Ctrl+C`、`Ctrl+X`、`Ctrl+V` も使用できます。コピーは新しい予定を作成し、切り取り後の貼り付けは元の予定を移動します。
- 試験用CSVでは画面内だけを変更し、SharePoint接続時はSharePointへ登録・更新します。

## 予定の上下配置

「予定表更新」を押すと「上下入れ替え」ボタンが有効になります。「上下入れ替え」を押してオン（青色）にした間だけ予定の右上に `↕` が表示されます。予定の文字・帯または `↕` をつかみ、別の予定の上半分または下半分へドラッグします。オンの間は予定全体が上下移動専用になり、日時変更用のつまみは非表示になります。日時を変更する場合は「上下入れ替え」をオフにしてください。マウス付近の青い線と、位置が変わる予定の薄い予告表示を確認してドロップしてください。日時・グループ・予定内容は変更しません。日々・週間は同じ日・同じグループ内、月間は同じ月・同じグループ内で操作できます。月間の複数日予定は帯全体が移動します。Escまたは枠外へのドロップで取り消します。

「上下入れ替え」をもう一度押すとオフになります。「更新終了」や接続先切替でもオフになり、次に更新を始めても自動でオンにはなりません。この操作モードは保存しません。配置はドロップのたびに保存するため、終了ボタンでまとめて保存する操作は不要です。

手動配置は表示ごとに独立しています。日々は日単位、週間は週内の各日単位、月間は月単位で保存し、月をまたぐ予定も月間の配置は月ごとに指定します。予定単位で移動し、段全体の挿入・移動は行いません。移動先で線や文字が重なる予定だけを、まず移動元の空いた段へ移し、入らなければほかの空き段へ配置します。同じ段にあった別時間帯・別日付の無関係な予定は元の段を維持します。

新しい予定は空きへ自動配置します。日時・文字サイズの変更などで重なった場合も、関係のない予定の段は維持します。段の途中が空いても自動で詰め直しません。削除済み・別グループへ移動済み・非表示の予定の配置は無視します。必要な段が増える場合、グループの高さは増えます。

保存は予定IDごとの段番号（`version: 2`、`positions`）です。従来の段一覧形式も読み込めます。次の並べ替え時に、そのグループの表示位置を引き継いで新形式へ保存します。「予定表配置設定」リストをすでに準備済みの場合、新形式への移行に伴うリストや列の追加変更は不要です。初めて導入する場合は、以下の準備が必要です。

予定の `↕` をクリックして対象グループを選び、「自動配置に戻す」を押すと、その日・グループ（月間はその月・グループ）の指定を解除できます。配置は印刷にも反映します。試験用CSVでは画面内だけに保持し、再読込・接続先切替・ページ終了で消えます。

SharePointでは、下記の「予定表配置設定」リストへ保存し、他の利用者は再読込で反映できます。読み込み失敗時は自動配置で表示し、並べ替えを無効にします。保存失敗・同時更新時は変更前の配置を維持し、再読込を案内します。配置変更は予定本体の操作履歴には記録しません。

### 共有配置設定リストの準備

既存リストに加えて、同じSharePointサイトにカスタムリスト **予定表配置設定** を作成してください。名称は `js/config.js` の `sharePoint.layoutSettings.listTitle` で変更できます。

| 内部名 | 種類・設定 |
|---|---|
| `Title` | 標準の1行テキスト。必須、**一意の値を適用する（重複禁止）**。同時初回保存の上書きを防ぐため必須の設定 |
| `LayoutJson` | 複数行テキスト。プレーンテキスト、変更履歴の追記なし |

初期項目は不要です。アプリが表示・期間ごとに作成します。閲覧者に読取権限、並べ替えを行う利用者に項目の追加・更新権限を付与してください。既存項目の同時更新はETagで検出し、勝手に上書きしません。

### SharePointリストの変更要領（上下入れ替え機能）

#### 変更が必要なもの

| 現在の状態 | 実施する作業 |
|---|---|
| 「予定表配置設定」リストがない | 下記手順でカスタムリストを新規作成する |
| リストはあるが `LayoutJson` 列がない | そのリストに列を追加する |
| `Title` の重複禁止が未設定 | 既存の同一Title項目を確認・整理したうえで重複禁止を設定する |
| リスト・列・重複禁止が設定済み | リスト構成の変更は不要。アプリの更新と動作確認を行う |

既存の「予定表」リストへの列追加は不要です。「予定表表示設定」「予定表組織設定」など、ほかのリストも今回の機能のために変更する必要はありません。

#### 1. 配置設定リストを作成する

リスト・列を作成できる管理権限で、予定表が接続するSharePointサイトを開きます。空の**カスタムリスト**を作成し、名前を **予定表配置設定** にします。予定本体に使うイベントリストとは別のリストです。すでに同名の配置設定リストがある場合は作り直さず、次の列設定を確認してください。

#### 2. 標準のTitle列を設定する

リストの列設定で、標準の「タイトル」列（内部名 `Title`）を開き、次のように設定します。

| 設定項目 | 設定値 |
|---|---|
| 種類 | 1行テキスト（標準列をそのまま使用） |
| 必須 | はい |
| 一意の値を適用する／重複禁止 | **はい** |
| 既定値 | なし |

`Title` 列を新規追加する必要はありません。この列にはアプリが表示・期間を識別するキーを保存するため、固定のタイトルや `default` を初期登録しないでください。

同じTitleの既存項目が複数ある場合は、各項目の `LayoutJson` を控え、残す配置データを決めて1項目に整理してから重複禁止を設定します。重複を残すとアプリは配置設定を読み込めません。

#### 3. LayoutJson列を追加する

**作成時の列名を英字の `LayoutJson` にして**、次の列を追加します。内部名を正確に合わせるため、最初から日本語名で作成しないでください。作成後に表示名だけ「配置データ」などへ変更することは可能です。

| 設定項目 | 設定値 |
|---|---|
| 作成時の列名・内部名 | `LayoutJson` |
| 種類 | 複数行テキスト |
| テキストの種類 | プレーンテキスト |
| 既存のテキストに変更を追加する（追記） | いいえ |
| 必須 | いいえ |
| 既定値 | なし |

すでに列がある場合は内部名・種類・追記設定を確認します。アプリが保存するのは `Title` と `LayoutJson` なので、ほかの列を新たに必須にはしないでください。データ項目の手動登録は不要です。

#### 4. 利用者の権限を確認する

| 利用者 | 配置設定リストに必要な権限 |
|---|---|
| 予定表を閲覧する人 | 項目の読取 |
| 上下入れ替えを行う人 | 項目の読取・追加・更新 |

配置は全利用者で共有します。自分が作成した項目だけを読取・更新できる設定では、ほかの利用者が保存した配置を扱えません。共同編集する利用者が対象の配置項目を読取・更新できる設定にしてください。上下入れ替えや「自動配置に戻す」のために項目の削除権限は不要です。

#### 5. アプリの設定と配布ファイルを更新する

`js/config.js` の `sharePoint.siteUrl` と、同じ `sharePoint` 内の次の設定を確認します。

```javascript
layoutSettings: {
    listTitle: "予定表配置設定"
},
```

リストを別の名前で作成した場合だけ `listTitle` を合わせます。列の内部名 `Title`・`LayoutJson` は実装で固定です。

上下入れ替え機能を初めて配布する場合は、更新済みの `index.html`、`css/style.css`、`js/app.js`、`js/config.js` と、新規ファイル `js/schedule-layout.js` を配布先へ反映します。配置設定リストは、更新版アプリを利用する前に準備してください。

#### 6. 保存と再読込を確認する

1. 更新版の予定表を開き、Ctrl＋F5で再読み込みします。
2. データ接続先を **SharePoint** にして、予定を表示します。試験用CSVでは共有保存の確認はできません。
3. 「予定表更新」→「上下入れ替え」の順に押し、確認用の予定を1件上下へ動かします。
4. 「配置を保存しました。」と表示されることを確認します。
5. 「予定表配置設定」リストに項目が作成または更新され、`LayoutJson` に値が入っていることを確認します。
6. 予定表を再読み込みし、変更した表示・期間で配置が保持されることを確認します。別の利用者でも同じ表示・期間を開いて再読込し、共有されることを確認します。
7. 確認が終わったら必要に応じて元の配置へ戻し、「更新終了」を押します。

配置はドロップのたびに保存され、「更新終了」やブラウザー終了後も残ります。日々・週間・月間の配置はそれぞれ別です。例として2026年9月29日の日々表示では、`Title` に `sharepoint:daily:2026-09-29` が保存されます。`LayoutJson` はグループなどの区分ごとに、予定IDと段番号を保持します。これらの値はアプリが管理するため手動編集は不要です。

従来の段一覧形式のデータは削除・再登録せずそのまま使用できます。次に並べ替えたグループから新形式に更新されます。「自動配置に戻す」は対象の手動指定を解除する操作で、予定本体は削除しません。

#### 読込・保存ができない場合

| 症状 | 確認する内容 |
|---|---|
| 「予定表更新」を押しても「上下入れ替え」が有効にならない | 配置の読込が完了したか、画面にエラーがないか。接続先サイト、リスト名、内部名 `LayoutJson`、読取権限を確認する |
| 配置設定のTitle重複エラー | 同じTitleの項目を1件に整理し、Titleの重複禁止を設定する |
| 最初の配置保存だけ失敗する | 項目の追加権限と、アプリが値を入れない追加必須列がないかを確認する |
| 既存配置の更新に失敗する | 項目の更新権限を確認する。同時更新のメッセージなら再読込後にやり直す |
| 再読込で配置が消える | 試験用CSVではなくSharePointを選んでいるか、保存成功の表示があったか、同じ表示・期間を開いているかを確認する |

## データ接続先

画面上部の「データ接続」で切り替えます。

- **試験用CSV**: `data/schedule.csv` を `XMLHttpRequest` で読み込みます。画面上では編集できますが、CSVファイルには保存しません。
- **SharePoint**: SharePoint REST APIを使用し、予定の読込・登録・更新・削除を行います。

SharePoint接続では、現在表示している日・週・月と期間が重なる予定だけを取得します。表示期間を移動すると、その期間の予定を再取得します。

最後に選択した接続先は `localStorage` に保存されます。保存しない場合は `js/config.js` の `rememberDataSource` を `false` にしてください。

### 起動時の接続確認とシステムログ

画面上部右側の「システムログ」で、接続確認や読込・保存・更新処理の記録を確認できます。予定の変更内容を記録する「履歴」とは別です。読取専用モードでも利用できます。

「設定」の「システムログの記録（全利用者共通）」で「ログ記録：オン／オフ」を切り替えられます。「予定表更新」モードで操作すると「予定表表示設定」リストの `Title=default` の `SystemLogEnabled` 列（はい/いいえ）に保存し、成功後に反映します。設定はブラウザーに保存せず、従来の端末別設定も使用しません。全利用者が起動時に読み込み、開いている画面は「ログ記録設定を再読込」で反映できます。起動時は共有設定の取得が完了するまで記録を停止します。接続先未設定・列不足・権限不足などで読み込めない場合はエラーを表示して現在の状態を維持し、切り替えを無効にします。保存失敗・競合時も状態を変更せず、再読込が必要です。オフの間は新しいログを記録せず、記録済みのログは引き続き閲覧できます。開始済みの処理は完了結果まで記録します。予定の読込・保存やSharePointの操作履歴には影響しません。

起動時に、予定表・組織設定・文字設定・上下配置設定・操作履歴・アクセスカウンターのSharePointリストと、アプリで使用する列の読取を確認します。試験用CSVを選択している場合はCSVの取得も確認します。SharePointサイトが設定または自動判定されている場合、CSV表示中もSharePointの接続確認を行います。接続先が未設定のSharePointリストや、設定で無効な組織設定は「対象外」と記録します。SharePointを予定の接続先として選択しているのに接続先が未設定の場合、通常の予定読込はエラーになります。

ログには日時・結果・対象のリスト名とサイト・処理・エラー内容を表示します。成功、エラー、注意、対象外、処理中を区別し、20秒経過しても完了しない処理は注意またはタイムアウトとして記録します。通常の読込処理による設定データの解析エラーや、保存時の権限不足・競合、JavaScript実行エラーも記録対象です。予定の件名・説明・保存するJSON本文はログに記録しません。

- 「接続を再確認」：読取確認を再実行します。CSVの編集中データや表示設定は再読込せず、アクセスカウンターも加算しません。
- 「ログを消去」：このブラウザーに保持しているシステムログだけを消去します。予定・上下配置・SharePoint操作履歴は変更しません。
- 「閉じる」またはEsc：ログ画面を閉じます。

最新300件を、このブラウザー・このページの `localStorage` に保持します。ページを閉じても残りますが、他の端末やブラウザーには共有しません。ブラウザーのサイトデータ消去で削除されます。保存が制限されている環境では画面内だけに保持し、その旨を表示します。SharePointにシステムログ用リストを追加する必要はありません。ボタンのエラー件数は、保持している過去のエラー記録も含む件数です。現在の結果は最新の記録で確認してください。

接続確認は読取の確認であり、すべての書込権限や列の詳細設定（Titleの重複禁止など）を保証するものではありません。実際の書込結果は保存時のログで確認してください。アクセスカウンターは従来どおり起動時に1回加算を試み、その結果も別途記録します。

配布時は、新規ファイル `js/system-log.js` と更新済みの `index.html`・`css/style.css`・`js/app.js` を反映してください。

**保存先の区別：** ログ記録のオン／オフは「予定表表示設定」、システムログの本文はブラウザー内に保存します。「システムログ」専用のSharePointリストは不要です。休日も「予定表配置設定」を使うため、専用リストは不要です。

列の「内部名」は下表の英数字と正確に合わせてください。日本語の表示名は任意です。`ID`、`Title`、`Created`、`Modified`、`Author`、`Editor` は既存の標準列を使い、同名の列を追加しません。下表の既定値・必須設定は、新規リストを用意する際の推奨設定です。アプリが値を保存する列以外に、追加の必須列を設けないでください。

### 文字・ログ記録設定リスト「予定表表示設定」

空のカスタムリスト「予定表表示設定」に次の列を用意します。フォント・文字サイズ・ログ記録設定は全利用者共通の1項目へ保存します。既存環境では `SystemLogEnabled` 列を追加し、`Title=default` の値を設定してください。ログ記録設定の列がなくても文字設定の読込・保存は継続できます。

| 表示名の例 | 内部名 | 種類 | 必須 | 列の既定値・設定 |
|---|---|---|---|---|
| 設定キー | `Title` | 1行テキスト（標準列） | はい | `default`。重複不可を推奨 |
| フォント | `FontFamily` | 1行テキスト（追加） | はい | `default` |
| 文字サイズ | `FontSize` | 数値（追加） | はい | `14`。小数点以下0桁、最小12、最大20 |
| ログ記録 | `SystemLogEnabled` | はい/いいえ（追加） | — | はい（オン） |

列の作成後、次の初期項目を**1件だけ**登録してください。列の既定値を設定するだけでは項目は作成されません。

| Title | FontFamily | FontSize | SystemLogEnabled |
|---|---|---|---|
| `default` | `default` | `14` | はい |

`Title` は小文字の `default` のまま使用します。該当項目が0件または複数件の場合、アプリは読込エラーにします。設定画面からの保存はこの項目を更新するため、項目は削除しないでください。

| FontFamilyに保存する値 | 画面の選択肢 |
|---|---|
| `default` | 標準（Yu Gothic UI） |
| `meiryo` | メイリオ |
| `gothic` | ＭＳ ゴシック |
| `mincho` | ＭＳ 明朝 |

`FontSize` は基準サイズの数値で、`12`・`14`・`16`・`18`・`20` のいずれかです。`px` は付けません。フォント列へ日本語の表示名は保存しません。

リスト名は `sharePoint.displaySettings.listTitle` で変更できます。`FontFamily`・`FontSize`・`SystemLogEnabled` の内部名と設定キー `default` は実装で固定されているため、変更しないでください。全閲覧者に読込権限、文字・ログ記録設定の変更者に更新権限を付与します。同時更新はETagで検出し、競合時は再読込してから保存します。文字設定とログ記録設定はそれぞれ対象の列だけを更新しますが、同じ項目のため相互の更新でも競合を検出します。これらの変更は現在、操作履歴リストへの記録対象ではありません。

### 共通アクセスカウンター

全利用者で共有する累計アクセス数を表示するには、SharePointカスタムリスト「予定表アクセスカウンター」を作成し、内部名 `VisitCount` の数値列を追加してください。標準の `Title` が `予定表`、`VisitCount` が `0` の項目を1件作成します。リスト名と項目タイトルは `js/config.js` の `sharePoint.accessCounter` で変更できます。全閲覧者に、このカウンター項目の読込・更新権限が必要です。

| 表示名の例 | 内部名 | 種類 | 必須 | 列の既定値・設定 |
|---|---|---|---|---|
| 対象 | `Title` | 1行テキスト（標準列） | はい | 初期項目に `予定表`。重複不可を推奨 |
| アクセス数 | `VisitCount` | 数値（追加） | はい | `0`。小数点以下0桁、最小0 |

`VisitCount` の内部名は固定です。アプリは初期項目を作成しないため、列作成後に上記の1件を手動登録してください。

ページを開いたときに1回加算します。画面内の再読込や表示切替では加算しません。同時更新で競合した場合はキャッシュを使わず再取得して最大5回試します。「アクセス 確認中」から、更新成功時は実数、失敗時は「アクセス 集計失敗」に切り替えます。SharePoint接続先が未設定なら「アクセス 未接続」です。カウンターの更新は、予定表の「読取専用」とは独立しています。

アクセス数が増えない場合は、右上の「システムログ」で「予定表アクセスカウンター」の `increment` を確認してください。読取の接続確認が成功していても、初期項目や更新権限が不足すると加算できません。

- 「初期項目がありません」：リストに `Title=予定表`、`VisitCount=0` の項目を1件作成します。既存の累計値は0に戻さないでください。
- 「アクセス数の更新」・HTTP 403：利用者に対象項目の更新権限があるか確認します。
- 「カウンター項目の読込」・HTTP 404：接続先サイトとリスト名を確認します。
- `VisitCount` の列不足・値不正：内部名が `VisitCount`、値が0以上の整数になっているか確認します。
- HTTP 412：同時更新が5回続いた状態です。次回ページを開いたときに改めて集計します。

「接続を再確認」は読取だけで加算しません。設定修正後はページを開き直し、`increment` が成功して実数に切り替わることを確認してください。この機能は累計カウンターで、利用者別のアクセス履歴をSharePointに保存する機能ではありません。

### 操作履歴リスト

予定の新規作成・更新・削除は、別のSharePointカスタムリスト「予定表操作履歴」に記録します。日々画面でのドラッグによる時刻・グループ変更や貼り付けも対象です。画面の「印刷」の横にある「履歴」から最新300件を確認できます。更新では変更前と変更後、削除では削除前の内容を表示します。操作者と操作日時は履歴リスト標準の「作成者」「作成日時」を使用します。

組織設定の追加・更新・削除も同じ履歴リストに記録します。対象リストを「予定表組織設定」として区別し、大・小グループ、各表示の行数、自動調整、表示順、有効状態の変更前後を表示します。設定の変更が成功した後に履歴を記録するため、履歴記録や整理に失敗しても設定変更は取り消さず、設定画面に警告を表示します。試験用CSVを選択中でも、SharePointに接続できる場合は組織設定の共有履歴を表示します。

履歴リストには標準の `Title` 列に加え、次の列を作成してください。内部名を正確に合わせ、`BeforeJson` と `AfterJson` は「複数行テキスト」のプレーンテキストとしてください。

| 表示名の例 | 内部名 | 種類 |
|---|---|---|
| 操作 | `Action` | 1行テキスト |
| 予定ID | `ScheduleItemId` | 1行テキスト |
| 予定リスト | `ScheduleList` | 1行テキスト |
| 変更前 | `BeforeJson` | 複数行テキスト |
| 変更後 | `AfterJson` | 複数行テキスト |

標準の `Title` は履歴の件名に使用します。追加する5列は必須を「いいえ」、既定値なしとし、`BeforeJson`・`AfterJson` はプレーンテキスト、変更履歴の追記なしで作成します。新規作成時の変更前、削除時の変更後は空欄です。`Action` には `create` / `update` / `delete`、`ScheduleItemId` には項目IDの文字列、`ScheduleList` には対象リスト名をアプリが保存します。列の内部名は実装で固定です。初期項目は不要です。

履歴は新規登録後、ID順で最新300件を残して古い項目を削除します。履歴リストの名称は `js/config.js` の `sharePoint.history.listTitle` で変更できます。予定の変更と履歴リストへの記録は別のRESTリクエストなので、履歴記録や古い履歴の削除に失敗した場合、予定の変更は取り消されず画面に警告が表示されます。操作する利用者には履歴項目の読込・追加・削除権限が必要です。リスト自体を削除する権限ではありません。同時操作時には一時的に300件を超えることがあります。試験用CSVでは新規作成・更新・削除を各10件含むサンプル履歴30件と画面内の操作履歴を表示しますが、SharePointへは保存しません。

### 予定リスト（旧単一リスト方式のみ）

この節の独自列は `groupCalendars: false` の場合のみ使用します。新しいグループ別方式は標準予定表をそのまま使用します。

終日入力を保存するため、予定リストに内部名 `AllDay` の「はい/いいえ」列（既定値: いいえ）を追加してください。`js/config.js` の `sharePoint.fields.allDay` に対応します。列追加前はSharePointの読込・保存がエラーになるため、先に列を用意してください。この列はアプリ独自の終日フラグです。

予定入力では開始日・終了日をカレンダーから選択できます（IE11対応）。時刻は0800～1700の15分刻みのプルダウン、または直接入力（0830 / 08:30）に対応します。直接入力は0000～2359まで可能です。「終日」を選ぶと時刻入力を無効にし、選択した開始日から終了日までを含む予定として扱い、日々・週間・月間の予定に時刻を表示しません。終日を解除すると入力済みの時刻を再利用できます。

既存のSharePoint標準「イベント」リストを使用します。アプリが読み書きする列は次のとおりです。

| 表示名 | 内部名 | 種類・設定 |
|---|---|---|
| タイトル | `Title` | 1行テキスト、必須 |
| 開始時刻 | `EventDate` | 日付と時刻（時刻を含む）、必須 |
| 終了時刻 | `EndDate` | 日付と時刻（時刻を含む）、必須 |
| 分類 | `Category` | 既存のイベント列を使用 |
| 場所 | `Location` | 1行テキスト、任意 |
| 説明 | `Description` | 複数行テキスト、任意 |
| 目的（入力グループ保存先） | `Purpose` | 1行テキスト、任意。なければ追加 |
| 終日（追加列） | `AllDay` | はい／いいえ、既定値「いいえ」 |
| 線種（追加列） | `LineStyle` | 1行テキスト、任意、既定値 `solid` |
| 線色（追加列） | `LineColor` | 1行テキスト、任意、既定値 `default` |
| 文字色（追加列） | `TextColor` | 1行テキスト、任意、既定値 `default` |

既存のイベントリストを「予定表」として使うか、実際のリスト名を `sharePoint.listTitle` に設定します。追加列は上記の内部名で作成します。特に独自列 `AllDay` は既存の終日イベント列とは別に必要です。初期項目は不要で、閲覧者には読込権限、予定の編集者には項目の読込・追加・更新・削除権限を付与します。

`LineStyle` と `LineColor` は新たに追加する1行テキスト列です。線種は `solid` / `dotted`、線色は `default` / `red` / `green` / `brown` を保存します。列が未追加でも既存予定は標準の青い実線として読み込めますが、標準以外の線を保存するには両列を追加してください。試験用CSVでは線の変更も画面内のみ有効です。

文字色は線色とは別に設定できます。SharePointに保存する場合は1行テキスト列 `TextColor` を追加し、`default` / `red` / `green` / `brown` を保存します。列がない既存予定は標準色で表示され、標準以外の文字色は列の追加後に保存できます。試験用CSVの文字色変更は画面内のみ有効です。

`ID` は既存の標準列を使用します。入力グループと反映先は `GP1科／GS班｜日々・週間・月間` の形式で「目的」列へ保存します。大グループだけの場合は `GP1｜日々・週間・月間` の形式です。作成者・作成日時・更新者・更新日時はSharePoint標準の `Author` / `Created` / `Editor` / `Modified` を読み取り専用で表示します。CSVにはこれらの情報がないため「情報なし」と表示します。バナーURL、位置情報、空き時間情報、重複予約のチェック、出席者、設備など、アプリで使用しない列は変更しません。

予定の読込時にSharePointのETagを保持し、更新・削除時に同じETagを送信します。読込後にほかのユーザーが予定を変更していた場合は上書きせず、再読込を求めるメッセージを表示します。

## 組織設定

組織設定はSharePointの「予定表組織設定」リストから読み込みます。画面上部の「設定」を開くと、設定の追加・編集・削除、表示順、有効状態、月間・週間・日々の初期行数を変更できます。SharePointへ接続できない場合は `config/organizations.js` をフォールバックとして使用します。

### 組織設定リスト

SharePointでカスタムリストを作成し、次の列を用意します。

| 表示名の例 | 内部名 | 種類 | 用途 |
|---|---|---|---|
| 大グループ | `Title` | 1行テキスト | 必須 |
| 小グループ | `TeamName` | 1行テキスト | 大グループだけの場合は空欄 |
| 月間行数 | `MonthlyRows` | 数値 | 1～50 |
| 週間行数 | `WeeklyRows` | 数値 | 1～50 |
| 日々行数 | `DailyRows` | 数値 | 1～50 |
| 行数を自動調整 | `AutoRows` | はい／いいえ | 初期値は「はい」 |
| 表示順 | `SortOrder` | 数値 | 小さい順に表示 |
| 有効 | `IsActive` | はい／いいえ | 無効な設定は予定表へ表示しない |
| 予定表サイトURL | `CalendarSiteUrl` | 1行テキスト | 任意。空欄は共通サイト |
| 予定表リスト名 | `CalendarListTitle` | 1行テキスト | グループの標準予定表名 |

リスト名と内部名は [js/config.js](js/config.js) の `sharePoint.organizationSettings` で変更できます。同じ大グループで「小グループなし」の共通予定表と小グループ付きの予定表を併用できます。

`Title` は標準列を使い必須、`TeamName` は任意とします。各行数列は必須・小数点以下0桁・最小1・最大50・既定値5、`SortOrder` は必須・小数点以下0桁・既定値0、`AutoRows`・`IsActive` は既定値「はい」を推奨します。小グループごとに同じ大グループ名を保存するため、`Title` は重複を許可してください。

作成する初期項目の例です。実際の組織に合わせて置き換えてください。

| Title | TeamName | MonthlyRows | WeeklyRows | DailyRows | AutoRows | SortOrder | IsActive |
|---|---|---|---|---|---|---|---|
| GP1 | （空欄） | 5 | 5 | 5 | はい | 10 | はい |
| GP2 | A班 | 5 | 5 | 5 | はい | 20 | はい |
| GP2 | B班 | 5 | 5 | 5 | はい | 30 | はい |

全閲覧者に読込権限、組織設定の変更者に項目の読込・追加・更新・削除権限を付与します。空のリストを正常に読み込んだ場合は共有グループが0件となり、`organizations.js` の設定には戻りません。必要なグループを初期登録してください。

フォールバック設定は従来どおり `config/organizations.js` で管理できます。予定表には `groups` の登録順、その中の `teams` の登録順で上から表示されます。

```javascript
window.YOTEIHYOU_ORGANIZATIONS = {
    separator: "／",
    groups: [
        /* 大グループだけ */
        {name: "GP1", monthlyRows: 5, weeklyRows: 5, dailyRows: 5, autoRows: true},
        /* 大グループ＋小グループ */
        {
            name: "GP1科",
            teams: [
                {name: "GS班", monthlyRows: 5, weeklyRows: 2, dailyRows: 2, autoRows: true},
                {name: "JN班", monthlyRows: 5, weeklyRows: 2, dailyRows: 2, autoRows: true}
            ]
        }
    ]
};
```

`autoRows` は省略時も `true` です。「行数を自動調整」が有効な場合、月間・週間・日々の各表示で予定に必要な行だけを表示し、予定がない場合はグループ名を残す1行だけにします。例えば月間行数が5でも、必要な予定行が1行なら残り4行は表示しません。無効な場合は `monthlyRows`、`weeklyRows`、`dailyRows` の行数を最初から確保します。どちらの場合も予定が設定行数を超えたときは、予定を欠落させないため必要数まで増やします。空白セルをクリックすると、その日付とグループを入力画面へ自動設定します。設定ファイル外のグループが既存予定に保存されている場合は、設定済みグループの後に追加表示して値を保持します。

## 設定

`js/config.js` の次の項目を環境に合わせて変更します。

```javascript
sharePoint: {
    siteUrl: "https://サーバー/サイト/サブサイト",
    listTitle: "予定表"
}
```

`siteUrl` が空欄の場合は `_spPageContextInfo.webAbsoluteUrl` を使用します。それも取得できない場合は、配置URL中の `SiteAssets`、`Documents`、`DocLib` などからサイトURLを推定します。確実に接続するには `siteUrl` を明示してください。

予定リストと組織設定リストの内部名を変更した場合は、それぞれの `fields` も変更します。表示設定・操作履歴・アクセスカウンターの列の内部名は実装で固定です。

### リスト作成後の確認

1. 5リストの名前を `js/config.js` の設定と照合し、必要な列と初期項目を用意します。
2. 利用者の権限で予定表を開き、接続先を「SharePoint」に切り替え、予定の読込と組織グループの表示を確認します。
3. 「予定表更新」→「設定」（現在の設定画面パスワードは `snk`）でフォントと文字サイズを選び、「文字設定をリストに保存」を押します。別のブラウザーで開くか「文字設定を再読込」を押して復元を確認します。
4. 予定を追加・更新・削除し、「履歴」に記録されることを確認します。アクセス数はページを開き直して増えることを確認します。

「予定表更新」や設定画面のパスワードは画面操作の制御です。実際のデータへのアクセス権限はSharePoint側で設定してください。

## 試験用CSV

`data/schedule.csv` の列構成は次のとおりです。

```text
ID,Title,EventDate,EndDate,Category,Location,Description,Purpose
```

- 文字コード: UTF-8（BOMあり・なしの両方に対応）
- 日時: `YYYY-MM-DD HH:mm`
- カンマや改行を含む値: ダブルクォートで囲む

ブラウザの制約上、CSVをサーバー上へ直接上書きしません。試験中の編集結果を保存する場合もSharePointへ切り替えます。

同梱のサンプルには、2026年9月・10月の平日について設定済みの全グループの予定を収録しています。土日に開始する予定はありません。GP2～GP5は平日1日4件、その他は平日1日1件です。全1,587件を日々に表示し、週間は794件（約50％）、月間は317件（約20％）に絞っています。GP1には日またぎ・週またぎ・月またぎの確認用予定もあり、これらは全表示に残します。サンプルを同じ条件で作り直す場合は次を実行します。

```powershell
node scripts/generate-sample-schedule.js
```

## 配置

リポジトリ一式を同じ構成のまま配置します。SharePointの読込・登録・更新・削除を使用する場合は、認証CookieとREST APIへ同一オリジンでアクセスできるSharePointサイト内への配置を基本としてください。

IISなどSharePointとは別オリジンのWebサーバーへ配置する場合、そのままではブラウザの同一オリジン制約によりSharePoint REST APIへ接続できないことがあります。別オリジンで運用するには、認証を引き継ぐ同一オリジンのリバースプロキシなどを別途用意してください。CORSを許可するだけでは、環境の認証方式によっては接続できません。

CSV読込もHTTP/HTTPS経由で行うため、`index.html` をローカルファイルとして直接開くより、Webサーバー上で確認してください。
